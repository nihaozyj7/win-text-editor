## 优化方案:语法高亮延迟渲染,消除滚动卡顿

**诊断**:词法状态已有缓存,但 token 与文本每帧重新分析:`CEditorWindow.cpp:2061` 每次 WM_PAINT 对每个可见行重调 `LexLine`;且冷启动时 `StateAfterLine`(:2072)可能一帧补算上千行。滚动/光标闪烁触发的整帧重绘全部同步在 UI 线程。

**改动**(均在 `src/CEditorWindow.h/.cpp`,不动其他分层):

1. **Token 缓存**:扩展 `VisualRow` 增加 `tokens`、`hlStateIn`、`highlighted` 字段。`BuildVisibleRows` 缓存命中(同 epoch/语言/stateIn)时直接复用,不调 `LexLine`。失效复用现有 `BumpVisualEpoch` 整代清空机制。

2. **滚动活跃检测**:`ScrollToLine`(含滚动条拖拽、滚轮路径)记录最后滚动时间戳。

3. **延迟高亮**:某行 token 未命中且处于滚动活跃期(最近 ~120ms 内有滚动)时跳过 `LexLine`,以纯文本默认色渲染(`highlighted=false`),并 `SetTimer`(~100ms);WM_TIMER 中停稳后 `InvalidateRect` 补算高亮后 KillTimer。

4. **冷启动限流**:`StateAfterLine` 单次最多补算 ~2000 行,超出则本轮放弃高亮,走延迟路径在停稳后补算。

**验证**:`cmake --build build` 构建;运行 editor.exe 打开测试文件,确认快速拖滚动条不卡、停稳后高亮恢复、编辑后颜色正确刷新。不涉及 PieceTable/LineIndex/Encoding 层,无需 core_tests(但仍会跑一遍确认无回归)。
